# Progress Reporting
[SPEC-08]

## Overview

[SPEC-08.01] The progress reporting system SHALL generate structured reports from project state (Beads issues and git history) to communicate progress to both humans and AI agents.

[SPEC-08.02] Reports serve two audiences:
- **Humans**: Status updates, action items requiring decisions, broadcast notifications
- **AI agents**: Context recovery for fresh sessions, understanding of current project state

## Report Generation

### State Extraction

[SPEC-08.10] The system SHALL extract state from:
- Beads issue tracker (task status, dependencies, holes)
- Git history (commits, changed files since last report)

[SPEC-08.11] State extraction SHALL be read-only and SHALL NOT modify any project state.

### Report Sections

[SPEC-08.20] A progress report SHALL include these sections:

| Section | Content |
|---------|---------|
| Summary | Overall progress percentage, quick status |
| Since Last Report | Newly completed tasks, new issues discovered |
| Holes | Open holes blocking work, recently resolved, metrics |
| Current State | Progress bar, ready work, blocked tasks |
| Files Changed | Git diff since last report |
| For Agents | Context loading instructions for fresh sessions |
| For Humans | Action items requiring human attention |

[SPEC-08.21] The "For Agents" section SHALL provide enough context for an AI agent starting a fresh session to understand project state and find ready work.

[SPEC-08.22] The "For Humans" section SHALL highlight decisions needed, holes requiring clarification, and any blocked work that needs intervention.

## Output Formats

### Markdown

[SPEC-08.30] Reports SHALL be written as timestamped Markdown files to a configurable output directory (default: `docs/progress/`).

[SPEC-08.31] File naming: `YYYY-MM-DDTHH-MM-SS-<trigger>.md`

[SPEC-08.32] A `latest.md` symlink SHALL always point to the most recent report.

### JSON

[SPEC-08.40] A machine-readable JSON companion SHALL be written alongside each Markdown report.

[SPEC-08.41] `latest.json` SHALL always point to the most recent JSON report.

[SPEC-08.42] The JSON format SHALL include structured data for programmatic consumption: task counts, completion percentages, hole counts, and ready work list.

## Trigger Modes

### One-Shot

[SPEC-08.50] Default mode: generate a single report and exit.

[SPEC-08.51] Manual trigger reason MAY be specified via `--trigger "<reason>"` for inclusion in the report filename and content.

### Watch (Daemon)

[SPEC-08.60] Watch mode (`--watch`) SHALL poll project state and generate reports when trigger conditions are met.

[SPEC-08.61] Configurable trigger conditions:
- Time interval (e.g., every 30 minutes)
- Number of tasks completed since last report
- Any issue completed
- Epic milestone reached
- Hole created
- All remaining work is hole-blocked

[SPEC-08.62] Watch mode SHALL be stoppable via standard signals (SIGINT, SIGTERM).

## Broadcasting

[SPEC-08.70] Reports MAY be broadcast to external channels after generation.

[SPEC-08.71] Supported broadcast channels:
- `file` — write to output directory (always enabled)
- `slack` — post to Slack via webhook URL
- `discord` — post to Discord via webhook URL
- `email` — send via configured SMTP
- `webhook` — POST to arbitrary HTTP endpoint

[SPEC-08.72] Broadcasting SHALL be disabled with `--no-broadcast`.

[SPEC-08.73] Broadcast failures SHALL be logged but SHALL NOT cause the command to fail (graceful degradation).

## Command Interface

### /dp:progress

[SPEC-08.80] The `/dp:progress` command SHALL accept:

```
/dp:progress                              # One-shot report
/dp:progress --trigger "Phase 1 complete" # With trigger reason
/dp:progress --no-broadcast               # File only
/dp:progress --watch                      # Daemon mode
/dp:progress --format json                # JSON only
```

[SPEC-08.81] The command SHALL return zero exit code on successful report generation.

## Integration

### With Spec Decomposition (SPEC-07)

[SPEC-08.90] When work items are generated by `/dp:decompose`, progress reports SHALL track completion against the decomposition plan.

[SPEC-08.91] Hole metrics SHALL report counts of open, resolved, and total holes from the decomposition.

### With Task Executor Skill

[SPEC-08.92] The `task-executor` skill SHALL read `docs/progress/latest.md` at session start for context recovery.

### With Workflow (Close Phase)

[SPEC-08.93] Progress reports MAY be generated automatically as part of the Close phase to document what was accomplished.

## Configuration

[SPEC-08.99] Progress reporting is configured via `.claude/progress-report.yaml`:

```yaml
triggers:
  interval: 30m
  tasks_completed: 3
  issue_completed: true
  epic_milestone: true
  hole_created: true
  all_work_hole_blocked: true

broadcast:
  file: true
  agent_brief: docs/progress/latest.md
  slack:
    enabled: false
    webhook_url: "${SLACK_WEBHOOK_URL}"
    channel: "#project"
```
